Putting the website live

A step-by-step guide for GoDaddy

Everything needed is in one zip file. There is nothing to install and nothing to build — the website is finished. This guide covers checking you have the right GoDaddy product, uploading the files, and what to do if something looks wrong afterwards.

The last section shows how to do the whole thing with Claude in Cowork, with prompts you can copy and paste.

Prepared by Raijin September 2026

The file you must not lose

.htaccess begins with a dot, which means most systems hide it by default. Without it the site still works, but it loses its security settings and — more visibly — every photograph falls back to a much larger file, so the site becomes slow. Section four explains how to confirm it arrived.

Section two

First, check what you have at GoDaddy

This takes two minutes and it is the step most worth doing. One of GoDaddy's products cannot host this website at all, and finding that out after a long upload is a frustrating way to find it out.

Sign in to GoDaddy and open My Products. Look at the section headings:

What you seeWhat it means
Web Hosting
with a cPanel Admin button		 Correct. Go to section three.
Websites + Marketing
(Website Builder)		 This cannot host an uploaded website. It only runs GoDaddy's own drag-and-drop pages. You would need to add hosting.
Only Domains You own the web address but have nowhere to put the site yet. You would need to add hosting.
If you need to buy hosting

The product to buy is Web Hosting on Linux, which is the one that includes cPanel. Not Managed WordPress — that is a WordPress installation, and putting this site into it means fighting the platform. Once the plan is active, a Web Hosting section with a cPanel Admin button appears on the Products page.

Because the domain is already registered in the same GoDaddy account, the connection between the address and the hosting is made for you. There are no DNS settings to edit.

Section three

Uploading the website

  1. Open cPanel. My Products → Web Hosting → Manage → cPanel Admin.
  2. Open File Manager, then double-click into the folder called public_html. This folder is the website — whatever is in it is what the world sees.
  3. Delete GoDaddy's placeholder page first. There is usually an index.html, a default.html, or a "coming soon" folder already sitting there. If you leave it, it keeps winning over the real site and you will think the upload failed.
  4. Upload manussa-site.zip using the Upload button. Wait for it to reach 100%.
  5. Extract it. Back in File Manager, right-click the zip → Extract. Then delete the zip itself; it is no longer needed.
  6. Visit the website address. It should be there.
If the upload stalls or fails

The file is about 64 MB, which is more than a browser upload always manages in one go. If it stops partway, use FTP instead — it is steadier and can resume. In cPanel, open FTP Accounts to get the server address, username and port, then use a free program such as FileZilla and drag the extracted files into public_html.

Section four

Confirm the hidden file arrived

File Manager hides .htaccess until you tell it not to.

  1. In File Manager, click Settings in the top right.
  2. Tick Show Hidden Files (dotfiles) and save.
  3. Look in public_html. You should now see .htaccess sitting beside index.html.

When you are finished, public_html should contain exactly this:

index.html404.html
robots.txtsitemap.xml

Section five

The padlock (HTTPS)

GoDaddy issues the security certificate itself. It can take a few hours after the domain is pointed at the hosting.

Once https:// works when you type it manually, you can make every visitor use it automatically. Open .htaccess in File Manager (right-click → Edit) and find this block near the top:

# <IfModule mod_rewrite.c>
#  RewriteEngine On
#  RewriteCond %{HTTPS} !=on
#  RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
# </IfModule>

Remove the # from the start of each of those five lines, and save.

Order matters here

Do this after the certificate is working, never before. Forcing HTTPS when no certificate exists makes the website unreachable for everyone, including you.

Section six

If something looks wrong

What you seeWhat it means and what to do
Plain text, no pictures, no styling The _assets or fonts folder did not extract. Re-extract the zip rather than re-uploading it.
GoDaddy's "coming soon" page The placeholder was not deleted. Remove it from public_html and refresh.
The old site, even after uploading Almost always the browser holding a cached copy. Try a private window, or wait ten minutes.
The site is slow, photographs take a while .htaccess is missing. See section four.
"Index of /" and a list of files index.html is in a sub-folder rather than directly in public_html. Move the files up one level.
Site unreachable right after enabling HTTPS The certificate was not ready. Put the # back on those five lines in .htaccess and wait.

One habit worth having

When something does not look right, take a screenshot and attach it rather than describing it. Claude reads screenshots well, and a picture removes most of the back-and-forth.

Section eight

Changing the site later

Nothing about this website stores information — there is no database, no accounts, no orders. That makes updating it simple: new files replace old ones.

When there is a new version, you will receive a new zip. Upload and extract it over the top, keep .htaccess, and that is the whole procedure. There is never anything to migrate and nothing that can be lost.

If the web address changes

Four files carry the address inside them, which search engines and link previews read: index.html, 404.html, robots.txt and sitemap.xml. Everything else is identical whatever the address. Ask for a rebuild rather than editing them by hand — it takes under a minute.

Questions

If anything in this guide does not match what you are seeing on screen, send a screenshot rather than working around it. It usually means GoDaddy has moved a button, and it is quicker to confirm than to guess.
