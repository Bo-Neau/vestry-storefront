MANUSSA — how to put this site on GoDaddy
=========================================

Everything in this zip is the finished website. There is no build step, no
database and nothing to install: it is HTML, CSS, images and one small
JavaScript file. Any host that serves files will serve it.

WHAT TO DO
----------

1. Log in to GoDaddy → My Products → your hosting plan → Manage → cPanel.

2. Open File Manager and go into  public_html

3. If there is a default GoDaddy placeholder page in there — usually
   index.html, default.html or a "coming soon" folder — delete it first.
   Otherwise the old page keeps winning over this one.

4. Upload manussa-site.zip into public_html, then right-click it →
   Extract. Delete the zip afterwards.

5. IMPORTANT — turn on hidden files so you can confirm .htaccess arrived:
   File Manager → Settings (top right) → tick "Show Hidden Files (dotfiles)".
   You should see a .htaccess sitting next to index.html.

6. Visit the domain. That is it.

WHAT SHOULD BE IN public_html WHEN YOU ARE DONE
-----------------------------------------------

    index.html          the site
    404.html            shown for a wrong address
    robots.txt          for search engines
    sitemap.xml         for search engines
    .htaccess           hidden — headers, caching, compression
    _assets/            every image, the stylesheet, the script
    fonts/              the two typefaces, self-hosted
    favicon.png
    apple-touch-icon.png

If _assets or fonts are missing, the page will load as unstyled text. That
means the extract did not finish — re-extract rather than re-uploading.

HTTPS
-----

GoDaddy issues the certificate; it can take a few hours after the domain
points at the hosting. Once https:// works, open .htaccess and uncomment the
mod_rewrite block at the top to force it. Do that AFTER the certificate is
live, not before — forcing HTTPS without one makes the site unreachable.

ABOUT THE ADDRESS BAKED INTO THIS BUILD
---------------------------------------

This build was made for:

    https://auracoreofficial.com

That address is written into the page in four places that have to be
absolute: the canonical tag, the Open Graph URL used by link previews, the
sitemap, and the structured data. They do not follow DNS — the site will
work perfectly on any domain, but those four will point at the wrong one.

If it is going anywhere else, say so and it takes thirty seconds to rebuild.
Or do it yourself:

    SITE_URL=https://your-domain.com npm run build

and upload the contents of dist/ again.

UPDATING LATER
--------------

Replace the files. Keep .htaccess. Nothing else is stateful, so there is
never anything to migrate.
