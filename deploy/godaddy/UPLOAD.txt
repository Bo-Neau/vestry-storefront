MANUSSA — putting the site on GoDaddy
=====================================

Everything here is the finished website: HTML, images, two fonts and one
small JavaScript file. No build step, no database, nothing to install.

STEP 0 — CHECK YOU HAVE THE RIGHT PRODUCT
-----------------------------------------

On the GoDaddy Products page, look at the section headings:

  "Web Hosting"  with a cPanel Admin button   -> correct, continue below
  "Websites + Marketing" / "Website Builder"  -> STOP. This product cannot
                                                 host uploaded HTML at all.
                                                 It only runs GoDaddy's own
                                                 drag-and-drop pages.
  only "Domains"                              -> you own the name but have
                                                 no hosting to upload to.

If it is Website Builder or domain-only, you need to add a Web Hosting
(Linux/cPanel) plan before any of this works.

STEP 1 — UPLOAD
---------------

1. Products -> Web Hosting -> Manage -> cPanel Admin
2. File Manager -> open  public_html
3. DELETE GoDaddy's placeholder first. It is usually index.html or a
   "coming soon" folder. If you leave it, it keeps winning over this site.
4. Upload manussa-site.zip, then right-click it -> Extract.
5. Delete the zip once it has extracted.

STEP 2 — CONFIRM .htaccess ARRIVED
-----------------------------------

It is a hidden file and File Manager hides it by default.

   File Manager -> Settings (top right) -> tick "Show Hidden Files (dotfiles)"

You should now see .htaccess next to index.html. Without it the site still
works; it just loses the security headers, the caching rules, and the AVIF
image type — which makes every photograph fall back to a much larger JPEG.

WHAT SHOULD BE IN public_html WHEN YOU ARE DONE
-----------------------------------------------

    index.html            the site
    404.html              shown for a wrong address
    robots.txt            for search engines
    sitemap.xml           for search engines
    .htaccess             hidden - headers, caching, compression
    _assets/              every image, the stylesheet, the script
    fonts/                the two typefaces, self-hosted
    favicon.png
    apple-touch-icon.png

If _assets or fonts are missing the page loads as unstyled text. That means
the extract did not finish — re-extract rather than re-uploading.

IF THE UPLOAD STALLS
--------------------

The zip is about 64MB, which browser uploads sometimes cannot finish. FTP is
steadier:

  cPanel -> FTP Accounts gives you the server, username and port.
  FileZilla (free) -> connect -> drag the extracted files into public_html.

THE DOMAIN BAKED INTO THIS BUILD
--------------------------------

This build is for:   https://manussa.com

Four things in a static site have to be absolute and cannot follow DNS: the
canonical tag, the Open Graph URL that link previews use, the sitemap, and
the structured data. The site WORKS on any domain — those four would just
name the wrong one, which only matters to search engines and link previews.

Only four files carry it. Everything else is identical whatever the domain.

  Going on auracoreofficial.com instead?
     Extract alt-domain-auracoreofficial.zip and copy its four files over
     the top of the ones in public_html. Nothing else changes.

  Going somewhere else entirely?
     Ask, and it is a thirty-second rebuild. Or run it yourself:
        SITE_URL=https://your-domain.com npm run build
     then upload the contents of dist/.

HTTPS
-----

GoDaddy issues the certificate once the domain points at the hosting; it can
take a few hours. When https:// works, open .htaccess and uncomment the
mod_rewrite block at the top to force it.

Do that AFTER the certificate is live, never before — forcing HTTPS without
one makes the site unreachable.

UPDATING LATER
--------------

Replace the files, keep .htaccess. Nothing is stateful, so there is never
anything to migrate.
